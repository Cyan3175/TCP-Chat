# TCP Chat 11.6

用 **WinUI 3（Windows App SDK）** 重写的桌面聊天客户端。

和 9.4 的 raylib 版最大的不同：**没有服务端**。程序把学校里已有的 **WebDAV 服务器**当成一块公共留言板 —— 每发一条消息就在远端目录里写一个 JSON 文件，每隔几秒列一次目录把新文件拉下来。不用开端口、不用装服务、不用内网穿透。

> 本文是**总说明**：功能、用法、编译、测试、已知限制都在这里。
> 每个版本的详细改动见 [Releases](https://github.com/Cyan3175/TCP-Chat/releases) 里的发布说明；文末有[版本历史](#版本历史)摘要。

---

## 快速开始

1. 下载 `TCP-Chat-11.6.exe`，**放在哪个目录都行**，双击即可（自包含，不需要装 .NET，也不需要 Windows App Runtime）
   > ⚠️ **文件名里不要有空格或括号**（浏览器下载常加 " (1)"）：Windows App SDK 在含空格的路径下定位不到程序自己的界面资源，会启动失败；遇到这种名字程序会弹框提示改名。
2. 首次启动会让你填昵称（顶栏「改昵称」随时可改）
3. 默认连到 `https://dev.zhaohans.cn`，消息目录 `nw集训/学生资料临存/tcp_chat`（**消息文件就放在这一层**，目录要事先存在）
4. **要保密就点「设置」→ 填加密密码**，收发双方填**完全一样**的密码

> - 设置与崩溃日志都在 **`%LOCALAPPDATA%\TCPChat\`**，exe 目录里不会生成任何文件；附件缓存在同目录的 `cache\` 下
> - 从 10.6 及更早升级：老的 `%LOCALAPPDATA%\TCPChat10\` 会**自动搬过来**（设置 + 附件缓存），老目录清掉
> - 从 10.2~10.5 升级：exe 旁边那份老 `settings.json` 会自动搬进系统目录并删掉

## 它是怎么工作的

```
  张三的电脑                     学校 WebDAV                   李四的电脑
 ┌──────────┐                 ┌────────────────────┐        ┌──────────┐
 │ 发消息   │ ── PUT ───────▶ │ tcp_chat/          │        │ 轮询     │
 │ (加密)   │                 │  msg_<时间>_<随机>.json ◀──────│ PROPFIND │
 │ 收消息   │ ◀─ GET ──────── │  {v,id,from,time,enc}│        │ (每 3 秒)│
 └──────────┘                 └────────────────────┘        └──────────┘
```

- **一条消息一个文件**：WebDAV 没有原子追加，所以不做“往一个日志文件里 append”，而是每条消息单独写 `msg_<unix毫秒>_<8位随机>.json`，天然没有并发写冲突
- **文件名即排序键**：时间戳前缀让目录列表天然按时间有序
- **同步**：定时对消息目录发 `PROPFIND Depth:1`，只对没见过的文件名发 `GET`，收到后反序列化并插到正确的时间位置
- **撤回**：`DELETE` 自己的消息文件
- **目录不会被自动创建**：填错或还没建会直接提示「聊天目录不存在」，免得在你的共享目录里凭空多出一个文件夹

## 11.6 更新

- **消息搜索**：顶栏新增搜索框（Ctrl+F 快速聚焦），输入关键字即可搜索正文、引用、昵称和时间。Enter 跳到下一个、Shift+Enter 上一个、Esc 退出搜索。命中项用高亮边框标记，当前项用强调色高亮。底栏实时显示匹配进度。

## 11.5.2 更新

- **修「别人的普通消息没有玻璃效果」**：列表回收气泡容器时，有些气泡只是换了 DataContext（没有重新触发 Loaded），而它们在滚出视野时已经被注销过 —— 于是再也没注册回玻璃层，屏幕上就是一块普通底色。现在 **DataContext 一变就重新注册**（注册本身也改成幂等），屏幕上的每个气泡都在玻璃层里了。（用玻璃层自检导出核对：别人的气泡已经出现在玻璃面列表里）
- **别人的气泡不那么"实"了**：色调不透明度从 0.80/0.74 降到 **0.58/0.65**（浅色/深色）—— 以前壁纸几乎透不过来，看着就是一块纯白（或纯黑）方块；现在壁纸的层次、模糊和折射都看得出来，对比度仍 ≥ 4.5:1（浅色最坏 5.7:1、深色最坏 4.7:1）。

## 11.5.1 更新

- **底栏不再显示「⚠ N 条无法解密（密码不一致）」**：解不开的消息在自己的气泡上已经写明了原因，底栏一直挂着这句警告只是噪音。计数本身还留着（自测日志里能看到），只是不再显示。

## 11.5 更新

- **本地消息缓存**：同步到的消息（服务器上那份原始 JSON）会存在 `%LOCALAPPDATA%\TCPChat\cache\msgs_*.json`，**下次启动直接显示，不用把整个目录重拉一遍**；缓存按聊天目录分开存，换目录不会串消息
- **对方撤回不会漏**：服务器上文件没了的消息会从缓存和界面里一起移除（服务器偶发返回空列表时不动手，免得误清）；自己撤回的也会同步从缓存删掉
- **修深色下语音条看不见播放三角**：那个三角以前绑的是气泡底色，开了液态玻璃后气泡底色是**透明**，于是三角也透明，只剩一个白圆点；现在改用气泡内部实底的颜色
- **修关掉液态玻璃后设置里的开关/滑块看不清**：白玻璃压在白底上轨道和圆钮都看不见；现在关掉玻璃时它们改画普通主题控件的样子（灰轨道 + 白钮 + 描边，打开状态是主题蓝）

## 11.4 更新（上一个版本）

- **LaTeX 公式真排版**：`$…$` / `\(…\)` 行内、`$$…$$` / `\[…\]` 块级；分数、根号、上下标、`\sum`/`\int`（块级上下限叠放）、`\left(…\right)` 自动放大、`aligned`/`cases`/`pmatrix` 环境、`\boxed`、重音、希腊字母与运算符符号表。分数线/根号/方框都是**画出来的**，放大不糊；写错或不认识的命令按原文显示，不会吞内容
- **洛谷那套 Markdown 扩展语法**：折叠框 `:::info[标题]`/`success`/`warning`/`error`（`{open}` 默认展开、可嵌套）、`:::align{center|right|left}`、`:::epigraph[——作者]`；代码块 `line-numbers` 行号与 `lines=6-9` 高亮；表格 `^` 向上合并 / `<` 向左合并、`::cute-table{tuack}` 竞赛表
- **程序图标**：从 MahApps.Metro.IconPacks 6.2.1 取字形（FontAwesome6 `CommentDotsSolid`），生成多尺寸 ico，exe / 窗口 / 任务栏 / 顶栏都用它
- **缩放**：`Ctrl +` / `Ctrl -` / `Ctrl 0` / **`Ctrl + 滚轮`**，60%~240%，正文/代码/表格/公式一起重排
- **修「深色切浅色后自己的消息看不见」**：气泡玻璃色调以前在容器第一次加载时被“抓死”，列表回收复用后会把「自己/别人」判错 —— 自己的消息被画成白玻璃 + 白字；现在**画的时候按当前消息取色**。另外昵称/时间在玻璃模式下加了跟主题走的衬底与专用字色
- **修根号的横线与粗细**：分数线的纵向位置、根号顶上那道横线以前差了半个线宽；根号那一笔以前按高度算粗细，内容一高就比横线粗一截 —— 现在粗细与横线一致、位置严丝合缝

## 功能

### 消息

- 文本消息：`Enter` 发送，`Shift+Enter` / `Ctrl+Enter` 换行，输入框最高 170 DIP 自动换行
- **Markdown 渲染**：标题 `#`、**粗体**、*斜体*、***粗斜体***、~~删除线~~、`行内代码`、==高亮==、H~2~O、x^2^、围栏代码块（语言标注 + 关键字着色，支持洛谷的 `line-numbers` 行号与 `lines=6-9` 高亮）、有序/无序/嵌套列表、`- [x]` 任务列表、表格（`:---` / `:---:` / `---:` 对齐，支持 `^` / `<` 合并与 `::cute-table{tuack}`）、引用块、`> [!NOTE]` 提示块、分割线、链接与裸网址、`![图](网址)`（自动下载显示）、脚注 `[^1]`、定义列表、`:::容器`、`:smile:` emoji 短代码
  · 纯文本消息走**快路径**，不会被当成 markdown（`3 - 2 = 1`、`1.5 倍`、`a_b_c` 原样显示）；单条超过 2 万字符自动退回纯文本，保证滚动流畅
- **LaTeX 公式**：见上方 11.4 更新；代码块里的 LaTeX 不会被排版，系统通知/引用里显示可读的纯文本（`\frac{a}{b}` → `a/b`）
- **洛谷扩展语法**：见上方 11.4 更新；和洛谷一样**不解析原始 HTML**（标签按普通文字显示）
- **文件传输**：点「📎 文件」上传任意文件（附件先传 `att_*`，再发一条引用它的消息）；图片/视频/音频/语音都在气泡里预览，文档类显示文件卡片；点开用系统程序打开，右键可「打开附件 / 另存为…」，撤回时附件一起删
- **语音消息**：点「🎤 语音」开始录，再点一下停止并发送（`.wav`，气泡里显示时长与播放按钮）；**麦克风权限自动处理** —— 没权限时弹窗并直接打开系统麦克风设置页，打开开关回到窗口自动开始录音
- **媒体预览**：图片直接显示；**视频取第一帧当缩略图**并盖播放角标；音频/语音显示成播放条
  > 实现说明：回车走 `PreviewKeyDown`（隧道）而不是 `KeyDown` —— TextBox 内部会先把 Enter 当换行标记为已处理，普通 `KeyDown` 收不到；换行只由预览层负责（否则 `Ctrl+Enter` 会插两个换行）
- **新消息提醒**：收到别人的新消息时弹系统通知（标题=昵称，正文=内容）并闪任务栏图标；翻历史和自己发的不打扰；系统关了通知权限也不影响收消息
- **引用回复 / 复制文本 / 撤回**：右键消息菜单（撤回会连服务器上的文件一起删）
- 自己的消息靠右蓝色气泡，别人的靠左浅色气泡，各带发送者与时间；解密成功的消息带一把小锁 🔒
- 新消息自动滚到底部（可在设置里关闭）
- **启动快**：本地缓存上次同步到的消息（11.5），打开就能看到历史，后台再补同步；对方撤回的消息会跟着服务器一起消失

### 界面

- 原生 WinUI 3 控件，跟随系统深浅色，也可在设置里强制浅色/深色；**设置对话框圆角**并跟随主题
- **次要文字都对过色**：深浅色下的发送者、时间、状态栏、引用块、失败红字分别配过，不会出现深色下看不清、或蓝气泡上压黑字；浅色下自己消息上方的昵称与时间也跟随主题（10.7 修）
- **液态玻璃**：顶栏、输入栏、状态栏、每个消息气泡都是独立注册的玻璃面（Win2D 效果链：背景采样 → 高斯模糊 → 湍流噪声 → 边缘遮罩 → 位移折射 → 叠色 → 饱和/对比 → 圆角裁切 + 高光 + 1px 亮边），背景优先用系统桌面壁纸，读不到就程序生成渐变；质量滑块 0~100 即时生效（湍流层数 1~4、模糊 0.6×~1.15×、渲染分辨率上限 1.0×~4.0×）；关掉就回到普通主题外观
  · **实测**（窗口 1107×744、5 个玻璃面）：质量 10 **3.7 ms** / 质量 60 **4.3 ms** / 质量 100 **5.1 ms** 一帧；带 50 个气泡的极端情况质量 60 约 29 ms，且只在玻璃面位置变化时重画，滚出视口的面直接跳过
  · **玻璃下的可读性（11.4 修）**：气泡色调按当前消息实时取色（列表回收复用容器时不会把「自己/别人」判错），昵称/时间在玻璃模式下有跟主题走的衬底与专用字色
  · **稳定性**：玻璃相关的回调（绘制、量位置、气泡注册）全部包了异常保护 —— 画玻璃出问题最多这一帧不画，不会把窗口带崩；XAML 未处理异常会写进 `%LOCALAPPDATA%\TCPChat\crash.log` 并保持程序存活
- **缩放（11.4）**：`Ctrl +` / `Ctrl -` / `Ctrl 0` / `Ctrl + 滚轮`，60%~240% 每档 10%，**正文/代码块/表格/公式/昵称/时间一起缩放**（重排而不是放大图片），比例写进 `settings.json`，底栏提示当前百分比
- **字体列表与应用**：设置里下拉选本机字体（下拉项用自身字体实时预览），选中后**所有界面**（顶栏、按钮、气泡、右键菜单、对话框、下拉框）一起跟随；代码块保持等宽；选了本机没装的字体会自动退回系统默认并在底栏说明
- **程序图标（11.4）**：见下方[程序图标](#程序图标)
- 顶栏显示连接状态灯与「已加密 / 未加密」，底栏显示消息条数 / 同步周期 / 上次同步时间 / 当前目录 / 解不开的条数；高 DPI 感知（PerMonitorV2），窗口按 DIP 居中

### 设置项

| 项 | 说明 |
|---|---|
| WebDAV 地址 | 例：`https://dev.zhaohans.cn`，匿名访问（不需要账号） |
| 消息目录 | 服务器上的相对路径，默认 `nw集训/学生资料临存/tcp_chat`；**要事先存在** |
| 昵称 | 显示在消息上，仅作为身份标识 |
| **密码列表** | 每行一个密码（**留空项 = 明文发送**）；收消息时按顺序逐个尝试，命中即用 |
| **默认用哪一个发送** | 从列表里选一把，加密只用它（其余只用来解开老消息） |
| 同步周期 | 1–120 秒，默认 3 秒，**改完立刻生效** |
| 历史天数 | 1–365 天，默认只加载最近 7 天 |
| 自动滚动 | 新消息到达时是否自动滚到底部 |
| 主题 | 跟随系统 / 浅色 / 深色 |
| 液态玻璃 | 开关（默认开）+ 质量滑块 0~100，拖动即时生效 |
| 字体 | 本机已安装的字体族（约 200 个），第一项是「（系统默认）」 |

设置保存在 **`%LOCALAPPDATA%\TCPChat\settings.json`**（系统统一位置，exe 目录保持干净）；缩放比例也存在这里。自测模式（`TCPCHAT10_TEST_SETTINGS` / `TCPCHAT10_TEST_DATADIR`）下读写都指向指定的测试位置，不碰真实设置。

## 端到端加密

| 项 | 说明 |
|---|---|
| 算法 | AES-256-GCM，带认证标签；密文被改动、被改名搬运都会解密失败 |
| 密钥 | `PBKDF2-HMAC-SHA256(密码, 盐, 100000 次)` → 32 字节；盐 = `SHA256("TCPChat10/v2|crypto|" + 消息目录)` 前 16 字节 |
| 每条的随机数 | 每条消息一个随机 96 位 nonce，同一句话发两次密文也不同 |
| 附加认证数据 | 消息文件名 —— 密文被复制到别的文件名下就解不开 |
| 上传内容 | `enc` 字段 = `AESGCM1:` + Base64(nonce‖密文‖tag)，**服务器上不存明文正文** |
| 明文部分 | 昵称与时间仍是明文（接收方要靠它显示「谁、什么时候发的」）；正文与引用加密 |
| 多密码 | 列表里的密码**都会用来尝试解密**（命中即用），**加密只用选中的那一把**。整体强度等于最弱的那把，所以正式用建议只留一把强密码 |
| 密码不一致 | 该条显示 🔒「无法解密：本机的加密密码与发送方不一致」，底栏统计条数，不显示乱码 |

**附件也一样加密**：设了密码时附件内容是密文（AES-256-GCM，消息文件名作为附加认证数据），文件名/大小藏在密文里。

## 编译与发布

需要 **.NET 10 SDK** + **Windows 11 SDK 10.0.26100**（或 VS 2022 Build Tools 带 UWP/WinUI 工作负载）。

```powershell
cd TCPChat10
dotnet build -c Release                    # 调试构建产物(文件夹形式, 便于反复启动)
dotnet publish -c Release -o ..\dist116    # 发布: 只产出一个 TCP-Chat-11.6.exe
```

关键工程设置：

- `WindowsPackageType=None`（免打包运行，双击 exe 即用）、`WindowsAppSDKSelfContained=true`（把 Windows App Runtime 打进去，目标机不需要预装运行时）
- `PublishSingleFile` + `IncludeAllContentForSelfExtract` + `EnableCompressionInSingleFile`（发布成**单个 exe**；代价是首次启动会把自己解压到 `%TEMP%\.net\TCP-Chat-11.6\` 下，之后复用）
- `ApplicationIcon` 指向 `Assets\app.ico`，控件与顶栏图标从**嵌入资源**里解出来（单文件发布时 exe 旁边没有 Assets 目录）
- 设置文件位置用 `Environment.ProcessPath` 定位 exe 目录 —— 单文件发布时 `AppContext.BaseDirectory` 指向的是 `%TEMP%` 里的解压目录，不能用
- `Markdig` 1.4.0（MIT）负责 markdown 解析，纯托管代码，单文件发布没问题

> WindowsAppSDK 版本必须 ≥ 2.5.1：1.7.x 上 `XamlCompiler.exe` 会静默退出码 1，构建直接失败。

## 已知限制与注意事项

- **加密只能保护正文**：昵称、时间、消息条数仍是明文，服务器管理员能看到「谁在什么时候发了多少条」；密码忘了就真解不开了（没有找回机制），换密码也不会重新加密历史消息
- **同一目录 + 同一密码 = 同一把钥匙**：密码是双方共享的口令，谁拿到密码谁就能解密；没有每用户密钥对 / 前向保密
- **消息目录是公开的**：知道 WebDAV 地址和目录名就能读到消息文件（加密后读到的是密文）。**不要在共享目录里发隐私内容**，除非开了加密
- **程序不会自动新建目录**：目录填错或还没建会直接提示，消息不会写到别的地方去
- **单文件 exe 首次启动稍慢**：会把自己解压到 `%TEMP%\.net\TCP-Chat-11.6\`（约 240 MB，之后复用；换新版本会再解一份），程序每次启动会自动清理自己以前留下的旧解压目录
- **消息不是实时推送**：靠轮询，默认 3 秒（1~120 秒可调，**改完立刻生效**），对方最多慢一个周期看到；服务器偶发把某个请求挂住几十秒时，客户端会自动跳过并在下一轮重试
- **历史只按文件名时间戳排**：客户端时钟不准会导致消息顺序错乱
- **附件与语音**：整份文件先读进内存再上传（几十 MB 没问题，超大文件请直接用资源管理器拷）；设了密码时附件也是密文上传
- **液态玻璃占一点 GPU**：效果链是 Win2D 画的，玻璃面越多/质量越高越吃显卡（核显也能跑，卡就把质量拉到 30 以下或关掉）；**桌面被全屏程序盖住时**（比如玩游戏）窗口本身不受影响，但截图工具通常抓不到 Win2D 的内容
- **视频缩略图**用 WinRT `MediaComposition` 取第一帧，取不到就退回文件卡片；**语音录制**需要系统麦克风权限 —— 非打包程序没有「每个应用单独询问」的弹窗，只有「设置 → 隐私和安全性 → 麦克风 → 让桌面应用访问你的麦克风」这一个总开关，所以点 🎤 时会自动检查并直接打开这个设置页
- **markdown 是「只读渲染」**：不执行 HTML（`<b>` 之类按原样显示，和洛谷一致），图片只支持 http/https 网址；单条超过 2 万字符自动退回纯文本
- **公式支持的是常用 LaTeX 子集**：自定义宏（`\def`）、`\ce{}` 化学式、`\begin{tikzcd}` 之类没做；不认识的命令**按原文显示**（不会把内容吞掉）
- **洛谷语法里没做的**：Bilibili 视频插入（当普通图片地址处理）、`[toc]` 目录；折叠框和洛谷一样默认收起，点标题展开
- **关闭窗口时偶尔会在系统事件日志里留一条 `CoreMessagingXP.dll (0xc000027b)` 崩溃记录**：11.3 及以前就有（用旧版 exe 对照验证过），消息与设置不受影响

## 9.4 及以前（raylib 版）

仓库根目录的 `TCP Chat9.4.cpp` 是基于 [raylib](https://www.raylib.com/) 6.0 + Winsock2 的 C++17 单文件实现，**自带服务端**、走原始 TCP 直连（默认端口 45678），功能包括多房间、私聊、断点续传、表情、搜索、托盘等。

```powershell
g++ "TCP Chat9.4.cpp" -o TCP-Chat-9.4.exe ^
  -I"raylib/include" -L"raylib/lib" ^
  -lraylib -lws2_32 -lwinmm -lgdi32 -lopengl32 -limm32 -lcomdlg32 -lshell32 ^
  -static -static-libgcc -static-libstdc++ -mwindows ^
  -O2 -std=c++17
```

两版各有取舍：9.4 需要一台机器当服务器、但消息不落地；10.x 不需要服务器、消息存在共享目录里（10.1 起可以端到端加密）。
